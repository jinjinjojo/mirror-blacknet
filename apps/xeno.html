synopsis

How it works

On launch, main.js requires xeno.node (an N-API wrapper) which LoadLibraryWs the real executor Xeno.dll. The DLL spins up a localhost HTTP server (cpp-httplib), a caching thread, and a BytecodePatchWatcher. The cache pulls a zstd-encrypted offset table ep.zst.enc from x3no.pages.dev, falling back to a Pastebin raw. On Attach: OpenProcess on RobloxPlayerBeta.exe, walk static offsets to DataModel → CoreGui → RobloxGui → Modules, find the locale translation ModuleScript, use VirtualAllocEx + NtWriteVirtualMemory to overwrite its bytecode field with a Luau-compiled bootstrap.

Exports — 6

Initialize

Boot the executor. Spawns worker threads: XenoServer (localhost HTTP), Caching, BytecodePatchWatcher.

Called from addon.cc on module require().

Attach

Find RobloxPlayerBeta.exe, OpenProcess, resolve offsets, locate CoreGui > RobloxGui > Modules, hijack translation module.

Returns success only after the Roblox-side bootstrap pings the local HTTP server.

Execute

Compile user Lua -> Luau bytecode (in-proc), patch bytecode into target client's ModuleScript via cross-process write.

The core RCE primitive. BytecodePatchWatcher auto-restores if Roblox overwrites.

GetClients

Return JSON array of currently attached RBXClient instances (one per Roblox window / multi-instance).

Polled every 200ms by main.js and streamed over IPC to the renderer.

SetSetting

Only two settings routed through the native layer.

Version

Shown in the UI header + logs.
