Textual breakdown

1 · User → React UI → preload.js

The user interacts with the CRA React build (Monaco + sonner + lucide). All renderer effects go through window.electronAPI, exposed by preload.js via contextBridge with contextIsolation=true, nodeIntegration=false.

2 · main.js (Electron main)

Owns BrowserWindow lifecycle, tray, taskbar overlay (per-attached-client badge), 27 IPC channels. Reads %LOCALAPPDATA%/Xeno/settings.json, auto-creates Start Menu shortcut.

3 · xeno.node (N-API addon)

Thin C++ wrapper. LoadLibraryWs Xeno.dll (path = XENO_DLL_PATH env or resources/public/Xeno.dll), then GetProcAddress-es each export. Only imports KERNEL32.dll (80 fns), no network of its own.

4 · Xeno.dll (the real executor)

x86-64 native C++, 2.4 MB, image base 0x180000000. Spins up 3 workers, runs a localhost HTTP server, maintains the cache, performs cross-process bytecode writes into Roblox.

  • Initialize — Boot the executor. Spawns worker threads: XenoServer (localhost HTTP), Caching, BytecodePatchWatcher.
  • Attach — Find RobloxPlayerBeta.exe, OpenProcess, resolve offsets, locate CoreGui > RobloxGui > Modules, hijack translation module.
  • Execute — Compile user Lua -> Luau bytecode (in-proc), patch bytecode into target client's ModuleScript via cross-process write.
  • GetClients — Return JSON array of currently attached RBXClient instances (one per Roblox window / multi-instance).
  • SetSetting — Flip a runtime setting. type=0 AutoAttach, type=1 DiscordRPC.
  • Version — Return the Xeno.dll build version string.

5 · Cross-process primitives

Xeno.dll never ships code into Roblox — it only writes Luau bytecode. No remote threads, no DLL injection, no shellcode.

OpenProcessAcquire handle to RobloxPlayerBeta.exe with PROCESS_VM_READ | WRITE | OPERATION.
VirtualAllocExReserve/commit a region in Roblox's address space for shellcode-free Luau bytecode blobs.
NtWriteVirtualMemoryPrimary cross-process write. Chosen over WriteProcessMemory to skip some kernel filters.
GetProcAddressResolve ntdll primitives at runtime (no static import).
ShellExecuteWOpen autoexec/workspace dirs from UI.

6 · Roblox-side (in-game)

The patched translation ModuleScript bootstrap connects back to http://localhost:<port> (the Xeno server), identifying itself as an attached RBXClient. Each user Execute ships a new compiled bytecode blob through that local HTTP channel; the bootstrap runs it in a LocalScript whose getfenv() wraps the Xeno global.
